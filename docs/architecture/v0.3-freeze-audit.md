# v0.3 freeze audit

Internal engineering record. Written at the end of the v0.3 architecture freeze,
against commit `1b3cab3` and its follow-up.

This is a point-in-time report, not a contract. The contracts are the other
documents in this folder; this says what state they were frozen in, what the
freeze cost, and what was knowingly left open.

## Files and modules changed

Thirty-one files. New: `src-tauri/src/benchmarks.rs`, `src/export/parseBody.ts`,
`src/export/buildDocument.test.ts`, `src/notes/IdClashNotice.tsx`,
`e2e/recovery.e2e.ts`, and ten documents in this folder. Substantially reworked:
`index.rs` (schema, every FTS query site), `vault.rs` (clash reporting, case
folding, `Relocated`, migration planning), `buildDocument.ts` (ordered sections),
`Editor.tsx` (the `onReady` coupling deleted).

## Migrations introduced

**None to the vault format.** `eid` is an added optional key, minted only when
evidence is next written — reading a v0.2 note does not rewrite it, asserted at
the byte level. `[[ULID|Title]]` is a form v0.2's parser already accepted; only
the writer changed.

**Index schema 8 → 9**, which is a drop-and-rebuild rather than a migration:
nothing in SQLite exists that is not already in a note. The two real migrations
(layout, citations) are unchanged in purpose, but are now both idempotent and
both back up first. See [migrations.md](migrations.md).

## Bugs the freeze found

Each was found by trying to prove the opposite of what the code claimed.

1. **A truncated index was judged usable.** `PRAGMA user_version` reads the file
   header, which survives a truncation that destroys every table, so a corrupt
   index passed the version check and failed later, mid-query.
2. **Saving a note scanned the whole vault, and so did asking for its
   backlinks.** `notes_fts` addressed rows through an `UNINDEXED` id column.
3. **An interrupted move could leave a figure that would not load.**
4. **A resumed migration would have flattened the vault.** The plan derived every
   note's folder from its chain of `parent:` claims, including notes with no
   claim, whose empty chain came out as the vault root.
5. **The citation migration kept no backup**, though it rewrites prose in every
   note in the vault and the invariant said every migration backs up.

## Unresolved architectural questions

1. **Chapter and thesis assembly is undecided.** Where does the order live — a
   `type: chapter` note with a `sequence:` of ULIDs, a view, or folder positions?
   The export path was built so all three work without changing the note model,
   but the decision itself is open, and it should be made before it is built
   rather than during.
2. **Transclusion.** If a chapter is a list of notes, does editing the chapter
   edit the notes? This one bears on whether a note stays the unit of truth.
3. **Citation → evidence.** `eid` exists; nothing points a `[@ref]` at one yet.
4. **Id clash repair.** Reported, never repaired. Mint a new id? Merge? Undecided.
5. **No stored format version, by design.** Detection is by content, which works
   for both existing migrations but has no answer for a future change that is
   invisible in content.
6. **`updated` versus filesystem mtime** can disagree after an external edit, and
   nothing reconciles them.

## Technical debt deferred

- `list_tags` re-reads the whole vault (3.9 s at 50k) although the index already
  holds `note_tags`. Easy win, not taken.
- Index rebuild is roughly 40% slower than v0.2 — trigger overhead, paid once per
  corrupt index.
- `owned_attachments` scans the whole vault on every move.
- `baseline_at_50k` takes thirteen minutes to build, so CI can never run it.
- "The vault never contains a credential" is verified by inspection, not by a
  test.
- A corrupt index another process holds open needs a person. See
  [recovery.md](recovery.md).

## Compatibility

v0.2 vaults open unchanged and are not rewritten. Downgrading is safe for prose,
links and folders — a v0.2 binary parses `[[ULID|Title]]` correctly and rewrites
it to the bare form on its next save — but it **silently drops `eid`s** on
re-save, because it has no such field. A v0.2 binary opening a v0.3 index sees a
version mismatch and rebuilds.

## Verdict: READY FOR v0.4

Every contract the freeze set out to settle is now stated with a test that holds
it, and the five bugs above were all in the frozen surfaces. Finding them is the
argument for having done this before v0.4 rather than after.

Two conditions, recorded as conditions rather than buried:

- **Decide chapter assembly before building it.** All three candidate shapes are
  compatible with the freeze; picking one mid-implementation is how a format
  decision gets made by accident.
- **`PlatformStore` has never been exercised.** Save a key, remove it, confirm
  Credential Manager is empty. Ten minutes, on Windows, by hand. Needed before
  v1, not before v0.4.
