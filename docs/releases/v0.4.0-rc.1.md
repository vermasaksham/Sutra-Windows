**A release candidate, not a release.** It exists so the v0.4 reading workflow
can be tried against a real Zotero library — which is the one thing its
automated tests cannot do.

## Install

Download **`Sutra_0.4.0-rc.1_x64-setup.exe`** and run it. Installing over 0.3.1
keeps everything, and no migration runs. Unsigned, so SmartScreen warns: **More
info → Run anyway**.

Your vault is untouched by this build unless you capture evidence into a note,
which writes to that note's frontmatter and nothing else.

To go back, install 0.3.1 over it. Notes written by this build stay readable:
the keys it adds to an evidence entry are optional and ignored by older builds.

## What is new: reading a paper, and taking evidence out of it

Open a Source note that came from Zotero and press **Read text**. The paper's
text appears where the note list was, a page at a time. Select a sentence and
**Capture as evidence** records it — the source's exact words, the page it sits
on, and an id of its own — on the note you were writing.

**Annotations** shows the highlights and notes you already made in Zotero.
Capture them one at a time; anything already captured is marked. Your own
comment on a highlight stays visibly separate from the paper's words, because
that distinction is the thing this app exists to keep.

Two things it deliberately does not do: there is **no bulk import** of
annotations, and capturing evidence does **not** write a citation into your
prose. Both were considered and declined — see `docs/design/` if you want the
reasoning.

## What this is a candidate for

It reads Zotero's own copy of a PDF for the first time, and that is the part
worth exercising:

- **Imported PDFs** — the ordinary case, a paper added to Zotero — are resolved
  from the attachment's own record. The shape of that record was verified
  against a real library; the rule built on it has not opened a real paper yet.
  That is what you would be testing.
- **Linked files** — a PDF Zotero points at rather than stores — are implemented
  from the documented behaviour and **not verified against real data**.
- A PDF that is **missing, scanned, password-protected, or unreadable** is named
  as such rather than reported as a fault.

## Still not done

The installer is unsigned. Updates are not automatic — and this build will not
be offered to anyone as one, because a candidate is not something to push at
people. No OCR, so a scanned paper stays a scan. Numeric citations are still
numbered per note rather than across a thesis.
