Nothing new. Everything here makes what Sutra already did more trustworthy.

## Install

Download **`Sutra_0.2.1_x64_en-US.msi`** and run it. `Sutra_0.2.1_x64-setup.exe`
is the same application with the other installer; take whichever you prefer.

Installing over 0.2.0 keeps everything. Your vault is a folder of markdown files
and **nothing in this build rewrites it**: no migration runs, no note is
reformatted, no citation is rewritten. The installer is still not code-signed,
so SmartScreen warns on first run: **More info → Run anyway**.

## Two things that were quietly losing work

**Re-importing a paper wiped its offline citations.** Every style Zotero had
ever rendered for a source was cached in the note so a draft written on a train
still reads "(Ko et al., 2024)" with Zotero closed. Importing that paper again —
which happens whenever you cite it from the picker a second time — replaced the
whole record and threw the cache away, along with the paper's collections and
the note of which PDF belongs to it. A re-import now *merges*: the library is
the authority on every fact it actually answered for, and silent about the rest.
A field the fetch had no answer for keeps the answer it already had, and nothing
is ever invented.

**Moving a note left its figures behind.** The markdown moved; the pictures
stayed in the old folder. They still displayed, so nothing looked wrong — until
you deleted or archived that old folder and every figure in the moved note went
with it. A note's own attachments now travel with it, and follow it into the
trash when it is deleted, where they can be dragged back out. An attachment two
notes share belongs to neither, so it is left exactly where it is: moving it
would fix one note by breaking another.

## Word export was losing content

Four faults, all of them silent. The PDF route (which prints the page) was never
affected — these were all in the Word document.

- **Inline formulas were torn out of their sentences.** "The bandgap is $E_g$
  eV" exported as "The bandgap is  eV" with a picture underneath it. Formulas
  now stay in the line, where they were typed.
- **A formula inside a quotation vanished entirely** — no picture, no text,
  nothing. Blockquotes are where a source's own words go, so this was losing
  evidence.
- **Tables were flattened to plain text.** Bold, italics, links, citations and
  formulas inside cells were all discarded. In a table of measured values with
  units, that is most of what the table said.
- **Links between notes exported as raw identifiers** — an italic
  `01HQ3M8K2P…` where a note's name belongs. They now export as the note's
  title. A link whose note has been deleted keeps its `[[id]]` visible rather
  than disappearing, because the reference really is in your file.

## Your API keys are no longer plain text

On Windows, the Zotero and assistant keys now go into **Windows Credential
Manager** rather than into Sutra's settings file. An existing key is moved there
the first time 0.2.1 runs, and the plaintext copy is removed **only after** the
credential store confirms it has the key — an interrupted migration leaves your
key working where it was rather than nowhere.

Settings → References and Settings → Assistant now say where each key actually
is, rather than assuming. If a save cannot reach the credential store you are
told, in words, instead of the failure being swallowed. Setting
`ZOTERO_API_KEY` or `ANTHROPIC_API_KEY` in your environment still stores nothing
at all and still wins over anything typed in.

Sutra's settings file is also now written the same atomic way notes are, so an
interrupted save cannot leave a half-written file that reads as "no vault, no
key, no fonts".

## Citation consistency

A note records what it cites twice, and it has to: `[@ref]` in your prose is the
mark in the sentence, and the entry in **Sources** is the provenance record with
the page and the source's own words. Neither can be derived from the other.

Sutra already told you when the prose cited something the record did not have.
It now also tells you the other way round — a source recorded and then cut from
the paragraph, still numbered in the reference list, cited by nothing.

**Nothing is fixed automatically, ever.** A half-written paragraph looks exactly
like a mistake, and deleting a page number and a transcribed quote to tidy up a
list is not a decision software should make. It says what disagrees; you decide.

## Smaller

- **A note moved or renamed outside Sutra is found again.** Drag a note in
  Explorer, or let a sync client move it, and Sutra used to lose track of it
  until the next full refresh — the note simply disappeared from search.
- **Creating a note no longer reads the whole vault.** It reads the one folder
  it is being created in. On a five-thousand-note vault that was five thousand
  files opened to work out a single number.
- **Links written as `[[id|Title]]` are now read correctly.** Sutra still
  *writes* the plain `[[id]]` form — turning your vault's links human-readable
  is a rewrite of every file and needs a preview and a way back, so it waits for
  0.3. Reading the shape a release early is what makes that migration safe.

## Still not done

- **The installer is unsigned**, so SmartScreen warns. Fixing it needs a
  certificate.
- **Updates are not automatic.** Sutra can tell you; it cannot install.
- **On Linux and macOS builds there is no credential store wired up yet**, so
  keys there stay in the settings file — and the app says so plainly rather than
  implying otherwise. Windows is the shipping platform.
- No OCR or PDF text extraction, no thesis assembly, no mobile app, no sync of
  its own.
- Numeric citations are still numbered per note, not across a whole thesis.
