The version the architecture was frozen at. Most of the work here is underneath
the floor — contracts written down, an index rebuilt, a migration taught to back
up first — but three things change what you see, and one of them changes bytes
in your notes.

## Install

Download **`Sutra_0.3.0_x64_en-US.msi`** and run it. `Sutra_0.3.0_x64-setup.exe`
is the same application with the other installer; take whichever you prefer.

Installing over 0.2.1 keeps everything. **No migration runs** — the vault format
is the one 0.2.1 wrote, and this build reads a 0.2 note back byte for byte
unchanged. The one change to your files happens as you save, and is described
next. The installer is still not code-signed, so SmartScreen warns on first run:
**More info → Run anyway**.

## Links become readable

0.2.1 promised this and deferred it. A link in your markdown was
`[[01HQ3M8K2P0QRSTUVWXYZ0001]]`; from 0.3 it is written
`[[01HQ3M8K2P0QRSTUVWXYZ0001|Growth of Sb2Se3 thin films]]`. Opened in Obsidian
or a text editor, a Sutra vault now reads as sentences rather than as a page of
26-character strings — Obsidian treats that shape as its own alias syntax.

It happens **as each note is saved**, not in a sweep. There is no preview step
and no backup because there is no bulk operation to preview: a note you edit
gains readable links, a note you never open is never touched.

- The id stays first and stays the only thing that resolves. A stale title can
  never send a link to the wrong note.
- **Renaming a note refreshes every link to it**, the next time each citing note
  is saved.
- A link whose note is gone keeps its bare `[[id]]`. No title is invented for a
  note that is not there.

The cost is real and worth stating plainly: saving a note written in 0.2 changes
bytes you did not type. It is additive, and it never alters what a link points
at.

## Chapters

`Ctrl+K` → **New chapter**. A chapter is a note whose frontmatter names other
notes in the order you want them read, and exporting it to Word produces those
notes as one document, in that order, with one bibliography.

Nothing is copied. The chapter holds ids, so a note keeps its place in the
sequence when you rename it or move it to another folder, and a position whose
note has been deleted is shown as an empty position rather than quietly closing
up — the chapter still claims something belongs there, and whether to drop the
entry or restore the note from the trash is yours to decide. Assembly is
read-only: a note's text changes in the note.

This is a foundation, deliberately small. There is no sidebar for chapters, no
chapter inside a chapter, no thesis-wide citation numbering and no automatic
numbering of the chapters themselves. It is not in the manual yet.

## Large vaults got much faster

Two operations you perform constantly were quietly getting slower as the vault
grew, which the new benchmark suite is what found. Reindexing a note you just
saved took 9.6 ms on ten thousand notes and now takes 1.7 ms; asking for one
note's backlinks took 23.2 ms and now takes 0.11 ms. Both were scanning the
full-text table through a column that had no index.

Saving, opening a note, backlinks and searching a rare term now cost the same at
fifty thousand notes as at one thousand, and there is a test that fails the build
if that stops being true. Launch still reads every file in the vault, and still
grows with it.

Your index is rebuilt once on first launch, which is not a migration: nothing in
it exists that is not already in your markdown. On a large vault it takes a few
seconds.

## When two files claim to be the same note

A sync client's conflicted copy, a bad merge, a note duplicated in Explorer —
and two files on disk carry the same id. Sutra used to open one of them and say
nothing. It now names both, at the top of the note list: which one it opened,
and which one is being shadowed.

Nothing is changed and nothing is deleted. The two are often not duplicates at
all — they are the morning's writing and the afternoon's — and which to discard
is not a decision this program gets to make.

## Smaller

- **Maths in a sentence.** `/inline`, or the `x²` button on the toolbar, starts
  a formula inside the line you are writing, caret already in it. `Esc` puts you
  back in the sentence just after it. Typing `$…$` still works; the button
  exists because the dollars are only obvious once somebody has told you.
- **Every piece of evidence recorded now carries its own id.** Additive, minted
  when a source entry is next written, and invisible until it is needed — it is
  what will let a citation point at one specific quotation rather than at a whole
  paper.
- **A truncated index is thrown away rather than trusted.** An interrupted write
  or a full disk could leave a database that reported the right version and then
  failed on the first search with "disk image is malformed". Sutra now checks it
  can actually be read, and rebuilds from your markdown when it cannot.
- **The citation migration backs up first.** It rewrites every note that has a
  Zotero key in it and, for two releases, it kept no copy. Both migrations now
  back up before touching anything, and both can be interrupted and run again.

## Still not done

- **The installer is unsigned**, so SmartScreen warns. Fixing it needs a
  certificate.
- **Updates are not automatic.** Sutra can tell you; it cannot install.
- **No PDF text extraction and no OCR.** Reading a paper's text out of a PDF is
  the next version's work.
- Numeric citations are still numbered per note, not across a whole thesis.
- No mobile app, no sync of its own.
- On Linux and macOS builds there is still no credential store wired up, so keys
  there stay in the settings file and the app says so. Windows is the shipping
  platform.
