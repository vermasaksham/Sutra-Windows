**The second release candidate.** Same reading workflow as rc.1, with the two
bugs found using it against a real library fixed.

## Install

Download **`Sutra_0.4.0-rc.2_x64-setup.exe`** and run it. Installing over
0.4.0-rc.1 or 0.3.1 keeps everything, and no migration runs. Unsigned, so
SmartScreen warns: **More info → Run anyway**.

Nothing in this build rewrites a file you already have. The title fixes below
are applied when a title is _shown_, so your existing papers read correctly
without their notes or filenames being changed underneath you.

## Fixed

**Chemistry in titles.** Zotero keeps a title's formatting as HTML, so a
materials paper arrived in the vault as
`Sb<sub>2</sub>Se<sub>3</sub> Nanosheet Film-Based Devices` and was shown
exactly like that — in the note list, in the note's own heading, in the reading
pane, and in the file name on disk. Subscripts and superscripts are now read as
what they are: **Sb₂Se₃**, **α-Sb₂O₃**, **Sb³⁺**, **10⁻⁴ S cm⁻¹**.

They become Unicode rather than being flattened to `Sb2Se3`, because a
subscript is the one part of a title whose meaning is carried entirely by its
position — `Sb₂Se₃` is a compound and `Sb2Se3` is a string that looks like one.
Where Unicode has no lowered form for a character, it stays on the line rather
than being replaced with something near it.

New papers get this at import, which also fixes the file name. Papers already
in your vault get it everywhere a title is displayed.

**"Source not in this vault", about a note that was in the vault.** A citation
was resolved against the list of _source_ notes only, so a citation pointing at
a note of any other type was reported as deleted — and two lists called it
`Reference 01M2…`, an internal id where a paper's name belongs.

Citations now resolve against every note in the vault. Three states are
distinguished where there was one:

- The note is there and typed **Source** — it is named, as before.
- The note is there and typed something else — it is named, and the panel says
  which type it is and to set it to Source.
- No note has that id — it says so, keeps the page and quote you recorded, and
  names the two places it could be (`.sutra/trash`, or a machine that has not
  synced yet). The id is still there to search for; it is no longer used as the
  paper's name.

A related gap: picking a paper from the `@` menu imported it and cited it in one
action, but nothing knew the new note until the app next read the vault — so the
sentence showed a raw id in the meantime. It resolves immediately now.

## Changed wording

**Read text** is now **Read paper text**, and reading mode says **Extracted PDF
text** above the paper's title — it sits where the note list was, and what is
below it is the paper's own words, not a note. The reminder that figures and
layout belong in Zotero stays. The layout is unchanged.

## Still what you would be testing

Reading an **imported** Zotero PDF has now been done against a real library —
one paper, opened, extracted and read. That part has moved from "implemented"
to "verified" in `docs/architecture/verification.md`.

Still unexercised against real data, and worth trying:

- **Zotero annotations** — importing a highlight, and its comment staying
  separate from the paper's words
- A PDF that has **moved** since Zotero recorded it
- **Zotero closed** while the pane is open
- **Linked files** — a PDF Zotero points at rather than stores

## Still not done

The installer is unsigned. Updates are not automatic, and a candidate is not
offered to anyone as one. No OCR, so a scanned paper stays a scan. Numeric
citations are still numbered per note rather than across a thesis.
